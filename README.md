## `/ philosophy`

Most people think the hardest part of software is writing code.

It's not. The hardest part is understanding the problem clearly enough that the code becomes obvious.

I've learned this the hard way — through 2,470 lines of Java written without shortcuts, through a project that broke the night before a demo and had to be rebuilt by morning, through 70+ LeetCode problems where the point was never the number.

I'm not chasing frameworks. I'm building fundamentals strong enough that the frameworks don't matter. I want to understand what's happening underneath — in the data structure, in the database call, in the model's decision boundary.

When I'm in a room, I want to be the person people look to. Not because I'm loud, but because I actually know my stuff. That standard drives me more than any deadline ever could.
